# 个人 / 团队工作台：需求与设计基线 v0.1

日期：2026-11-15（Asia/Shanghai）  
状态：本文定义已确认的产品边界和待实现的目标；当前仅有本地开发原型，尚不能作为可试点或生产系统。实现现状与剩余任务见 [实施计划](workbench-implementation-plan-v0.1.md) 和 [README](../README.md)。

> 已确认：工作台只有一个长期负责人；同事通过链接进入非管理员临时会话，不建设同事长期账号或项目成员管理。已有内容默认不公开；访客只能查看负责人明确开放的内容。详见 [单负责人、临时访客说明](single-owner-temporary-sessions.md)。

## 1. 产品目标

将负责人的知识、工作方法和有限授权转化为一个目标上持续在线的工作台：当联系不上负责人时，同事仍能自助获得有出处的回答、登记结构化问题、提交允许后台执行的任务，并查看负责人亲自维护的当前进度与投入。

产品提供可追溯的协助，不替负责人作出未授权的工程决定。目标是让答案、任务、产物和批准可追溯到发起会话或负责人、依据、授权范围、执行情况及验证结果；临时会话标识不等同于已核验的真实同事身份。

## 2. 已确认需求与设计假设

### 2.1 已确认需求

| 编号 | 需求 |
|---|---|
| R01 | 工作台在负责人不可联系时，支持同事自助问答、登记问题和提交后台任务。 |
| R02 | 项目知识支持 Markdown、Word、PowerPoint、TXT 和直接对话导入。 |
| R03 | 知识支持可视化管理，按项目区分，覆盖需求分析、设计、实现方案与实现细节。 |
| R04 | 知识之间可关联，能追溯需求到设计、实现及验证依据。 |
| R05 | 单独提供“关于我 · 当前工作状态”，展示负责人的进度和投入。 |
| R06 | R05 的内容只能由负责人本人手动录入和修改；文件、知识对话、Agent、后台任务均无写入路径。 |
| R07 | 系统采用有审计、人工参与的授权执行机制；默认不开放通用自主操作。 |

### 2.2 为形成可实施方案采用的默认建议

- 工作台只有一位长期负责人；同事通过链接使用临时访客会话。项目是知识组织边界，访客只能查看负责人明确开放的内容。
- 生产环境负责人身份、临时会话和审批机制仍需设计与验证；任何访客、代理或自动化都不能修改个人工作状态。
- 首版运行在持续在线的主机，Web 与 Worker 独立进程；不依赖个人电脑或聊天窗口在线。
- 先用脱敏样例和模拟模型开发完整闭环，再接入批准的真实模型及工程数据。
- MDE 暂按模型驱动开发理解。关联模型、生成器、配置、代码及测试版本，具体工具链通过适配器补充。
- 首版采用 React / TypeScript 前端、Python / FastAPI 服务和 Worker、PostgreSQL、可替换的对象存储。
- 所有新增条目默认草稿；负责人可预览后批量发布，避免逐段审批。
- 未被有效知识或有效产物引用的原始 / 临时文件默认保留 90 天；已发布知识及其证据来源在有效期间共同保留，审计事件默认 365 天。以上是试点建议，接真实数据前按组织规定配置。

除明确标注的已确认方向外，技术栈、部署位置和保留期限属于方案建议，不能视为用户或组织已批准的生产条件。

### 2.3 实施调整：Agent 与长期记忆

- Agent 运行时计划采用 Pi，通过独立适配层与工作台连接；模拟模式和工具授权边界继续保留。已接入只读问答的本地原型，完整工具授权与生产集成仍未完成。
- MVP 不安装、运行或调用 EverOS，也不把它作为启动条件。当前本地原型已提供按项目查询明确对访客开放的已发布知识，返回相关原文和来源；默认是有上限的提取式检索；显式启用模型时，可通过只读 Pi 基于这些片段生成带引用的回答，仍不等同于完成全部问答能力。
- 在问答 / Agent 与记忆实现之间保留可替换的接口边界；日后如需接入 EverOS，再评估具体 API 和部署，不预先创建依赖或宣称已经兼容。
- 任何未来记忆实现都必须受服务端身份与项目 ACL 约束，并保留可核验来源；不得写入个人工作状态，也不能自动把记忆提升为已发布工程知识。

## 3. MVP 范围与验收

### 3.1 功能范围

1. 项目空间、负责人和临时访客访问、知识条目、来源文件和版本管理。
2. 文件导入、对话整理、预览、分类、关联、批量发布及停用。
3. 项目树、列表与详情、围绕单个需求的关联图、缺项视图和版本比较。
4. 仅使用授权且已发布知识的问答，附来源定位；无依据时说明并允许转为问题单。
5. 问题登记、补材料、分诊建议、业务状态跟踪和关联任务。
6. 三种后台任务：日志分析、问题分诊、交接材料整理。
7. 关于我的手动状态编辑、手动发布、按周投入展示及按项目展开。
8. 持久化执行、审批、审计、重试、取消、结果验证和人工验收。

### 3.2 暂缓的能力

- 自动改代码、提交或合并变更、发布软件、变更工程基线、操作车辆或台架。
- 任意 Shell、任意网络访问、任意安装工具、自动扩展权限或修改 Skills。
- 开放式多 Agent 调度、复杂 PLM / ALM 平台替代、实时编辑 Office 文件。
- 从项目活动推断个人投入、从聊天自动更新个人状态。
- 不受负责人明确发布范围约束的公开访问、跨组织共享、全局自动合并不同项目知识。

### 3.3 验收样本与门槛

- 用 20 个脱敏真实问题、10 份日志、10 张历史问题单进行试点评测，记录人工判断结果与失败类别，不预先声称问答准确率。
- 权限测试必须覆盖检索、原文件、引用、图关联边、历史版本、导出和产物下载，越权均被拒绝。
- 支持五类知识来源；旧版 .doc / .ppt 通过转换任务进入同一预览流程，转换器缺失时返回明确状态及转换后重传入口。
- 选中需求后能找到其已关联分析、设计、方案、实现和验证；缺失项显示“未关联”，不等同于实际未完成。
- 访客、Agent 和导入任务均不能写入“关于我”；项目任务成功不会改变个人进度。
- 任务在关闭浏览器、刷新页面和 Worker 重启后仍可追踪；任何失败不得展示为已通过验证。

## 4. 信息架构与界面

### 4.1 导航

| 导航 | 内容 |
|---|---|
| 我的工作台 | 待审批、待验收、待补材料及失败任务；仅展示当前用户有权处理的事项。 |
| 项目空间 | 项目概览、模块树、需求及关联知识、问题、任务、基线。 |
| 问一问 | 先选项目及可选基线，再问答；保留来源及转问题单入口。 |
| 问题中心 | 登记、分诊、负责人、状态和关联任务。 |
| 任务中心 | 模板提交、执行状态、证据、产物、验证和验收。 |
| 关于我 | 发布的个人工作状态；仅本人可见编辑入口。 |
| 负责人管理 | 来源、导入作业、知识发布、项目、问题、模板和审计；仅负责人可维护。 |

### 4.2 项目知识空间

项目下包含项目背景、术语和架构原则，以及模块 / 功能域。模块内管理需求与知识条目。知识类型为：需求、需求分析、设计、实现方案、实现细节、验证记录、经验 / FAQ、决策记录。

- 左侧：项目与模块导航树。
- 中间：列表或当前需求的局部关联图；可按类型、状态、负责人和版本筛选。
- 右侧：正文、来源预览、关系、版本、关联问题和任务。
- 缺项视图：显示未关联分析、设计、实现或验证的需求，并显示负责人及待复核项。
- 目录是浏览结构，关系为多对多；一个设计可满足多个需求，不复制正文。

关系类型固定为：analyzes、designs_for、implements、verifies、depends_on、supersedes、references。每条关系必须记录方向、两端条目及其版本、创建者和确认状态。AI 可建议关系，发布前由负责人确认。跨项目关系不进入首版；内容开放或撤销时重算访客可见边，不能暴露未开放节点的标题或数量。

### 4.3 工程模板

| 类型 | 默认字段 |
|---|---|
| 需求 / 分析 | 场景、范围、约束、验收标准、未决问题。 |
| 设计 | 架构、接口、数据流、状态机、候选方案、取舍及决策依据。 |
| 实现方案 | 工作拆解、职责、依赖、实施顺序、验证计划。 |
| 实现细节 | 模型 / 文件位置、生成器、配置与代码版本、关键逻辑、注意事项。 |
| 验证记录 | 基线、环境、样例、命令或测试、结果、日志与遗留问题。 |

允许信息不完整，缺失字段记录为 unknown 或空值，不由模型编造。知识发布状态与工程完成状态分别存储；发布实现说明不表示实现已完成或通过验证。

## 5. 文件与对话知识导入

### 5.1 输入与定位

| 来源 | 提取与预览 | 引用定位 |
|---|---|---|
| .md | 标题、正文、表格、代码块，保留图片关系；清理不安全 HTML，不执行嵌入脚本。 | 来源版本、标题路径、行区间。 |
| .txt | 编码检测及可人工更正；按段落组织。 | 来源版本、行区间。 |
| .docx | 标题、段落、表格；修订或批注单独列出供处理。 | 来源版本、段落 / 表格锚点；不使用可能随排版改变的页码充当稳定锚点。 |
| .pptx | 幻灯片文本、表格、页面图像；备注默认不纳入正文，负责人可预览后选入。 | 来源版本、幻灯片号、元素锚点。 |
| .doc / .ppt | 隔离转换，保留原始与转换后文件及摘要；禁止运行宏。 | 原文件和转换版本对应的锚点。 |
| 对话 | 显式选择“整理为项目知识”，形成可编辑草稿并保存用户选定的消息快照。 | 消息快照 ID、知识版本。 |

密码保护文件需要用户提供可读取副本；解析失败、转换器缺失、未知编码不允许静默导入空正文。首版上限建议单文件 50 MiB、单批次 20 个文件；压缩展开上限 250 MiB，作为可配置、受测试的资源预算。远程引用和链接不自动抓取。

PPT 架构图、状态机和图表保留原图。图像识别或 OCR 解释是候选知识，在预览中明确标识；未经负责人确认不能作为已批准工程结论发布。含未解决修订的 Word 在发布前要求明确选定最终正文；不自动把修订内容当成最终事实。

### 5.2 导入与发布流程

1. 选择项目、模块 / 需求、类型、适用版本和可见范围，上传或选定对话内容。
2. 原始来源落对象存储并创建持久 ImportJob，后台解析。
3. 生成草稿条目、片段、定位、候选分类和候选关系。
4. 预览原文与整理结果；检查缺项、重复和潜在冲突。
5. 负责人修改后按整批或单条发布。发布者确认记录作为该版本的知识批准依据，不额外要求逐片段审批。
6. 只有已发布、未停用且当前用户可访问的版本进入检索。

相同内容摘要提示重复。再次导入同一来源创建新版本，旧版保留。冲突检测仅作建议；系统不得默默覆盖旧结论。来源的敏感等级和访问范围约束衍生知识及产物，不能通过摘要扩大受众。

保留策略的候选方案（试点前须确定）：有效已发布知识引用的 SourceVersion 必须固定保留原文件和定位资料，不受普通 90 天清理影响；未归档问题的附件同样固定保留。答案和普通任务产物默认保留 90 天，在有效期间固定保留其证据，需长期使用时可人工转为已发布知识。引用全部失效后从失效时间起计 90 天再清理。审计只保留元数据与摘要，不永久固定原文件。显式撤销 / 删除及组织强制清理优先于固定保留：先停用依赖知识、答案和产物，基线显示缺口，再按要求清理，不允许静默留下失效引用。

### 5.3 生命周期和基线

知识：draft → in_review → published → retired；负责人可从 draft 直接发布到 published。复核、驳回分别回到 draft 并保留审计。published 正文不可原地修改，变更创建新版本。

工程状态：proposed / in_progress / implemented / verified，手动维护且与发布状态分开。

复核标记：current / review_required。上游变更只标记受影响下游待复核，并显示原因，不自动修改下游正文或工程状态。

项目基线是条目版本及关系的冻结集合，修改产生新基线；首版由负责人手动创建。查询显式指定 baseline_id 时按该集合读取，缺省按每个条目的当前有效发布版；两者不得混用。基线不能绕过撤销或当前 ACL，发现已撤销来源时显示缺口并停止将其用作答案依据。

## 6. 关于我：仅本人手动维护

### 6.1 内容与展示

个人页面支持当前重点、事项优先级、阶段、完成内容、下一步、阻塞、里程碑、可协作时间和补充说明。进度百分比可选，范围 0–100，完全由本人填写。

投入按周、按项目及事项记录。每条投入选择 hours 或 percent；planned 与 actual 分开。小时与百分比不可直接相加，未填 actual 不等于 0。首版百分比仅表示本人填写的时间分配；不推断工作效率，不从提交次数、任务耗时或在线状态估算实际投入。

可视化展示已授权的已发布事项、周投入分布及按项目展开详情。不同单位和计划 / 实际分开展示；在用户只能看到部分项目时不展示泄露其他项目的全局总量或推算剩余投入。

### 6.2 写入边界

- 独立 PersonalStatus 与 PersonalStatusVersion；独立的人类会话表单编辑与发布接口。
- 只有经过验证的负责人本人会话可新增、修改、发布或撤回；临时访客、自动化和其他管理机制没有内容写权限。
- 文件导入、知识整理对话、Agent、MCP、Worker、事件回调、任务状态同步均不提供此模块的写入工具或调用路径。
- 服务端根据真实身份、凭证类型和接口用途授权，不信任客户端提交的 owner_id 或 source=manual；浏览器会话须有 CSRF 防护。系统只保证受控自动化链路无写权，不能仅靠一个字段证明人是否在操作其本人凭证。
- 内容状态只有草稿、已发布与已撤回；必须由本人手动发布。保留版本历史。
- 更新时间是服务端记录的元数据；可显示“待更新”提示，但不改变原文、进度或投入。
- 关联项目或任务仅用于导航。项目任务成功、延期或失败均不改变个人状态。
- 问答仅能读取访问者有权查看的已发布内容，并注明截至哪次手动更新。

默认仅负责人可见；负责人明确开放并发布后，临时访客才可查看所选内容。关联项目的投入须由负责人逐项选择是否开放；未开放的项目名称、事项及其统计不得泄露。

## 7. 问答、问题与任务

### 7.1 问答

请求必须包含 project_id 或明确选择个人状态问答。检索前按身份、项目、知识发布及撤销状态过滤，展示引用和下载时再次校验。问题不明确时询问必要基线或说明本次使用的版本。

Answer 保存文字、实际证据片段、知识版本、来源定位、检索 / 策略版本及验证结果。没有充分依据时输出缺失信息及建议下一步，不输出假出处。转问题单时只带入提交者有权读取的内容。

### 7.2 问题单

字段：项目、模块、需求、平台 / 变体、目标环境、模型版本、生成器版本、配置版本、仓库 / 提交、预期 / 实际、首次发现、复现步骤、证据、影响、紧急程度、提交人、负责人及待补材料。

业务状态：new → needs_info → triaged → in_progress → resolved → closed。允许 needs_info → triaged，resolved → in_progress 重新打开；每次迁移记录 actor、reason、version。Agent 仅建议分类和下一步，不能自行认定问题解决或关闭。

### 7.3 三个任务模板

| 模板 ID | 输入 | 输出 | 验证 |
|---|---|---|---|
| analyze_build_log | 项目、日志、可选基线及环境。 | 现象、时间线、证据、根因假设、反证 / 缺失信息、验证步骤。 | 所有证据行号或记录 ID 可定位；假设和事实分开。 |
| triage_mde_issue | 问题单版本、已有附件。 | 分类建议、缺项、关联知识、排查清单。 | 不编造版本、不改变问题状态或负责人。 |
| prepare_handoff | 明确选择的问题、知识和证据。 | 交接报告、待决策项、下一步。 | 引用可访问、不扩大来源受众、不自动发布为知识。 |

首版统一预算建议：每执行代次累计最多 12 个模型动作步骤、每次 Run 最长 600 秒、单 Worker 并发 2、可重试基础设施错误最多自动重试 2 次。成本预算以可配置 token / 费用上限实施，重试不重置该代次累计预算；模型未配置时禁止真实调用。预算是上限，不要求用完。

任务状态：

    submitted → validating → needs_input | awaiting_approval | queued | rejected
    needs_input → validating
    awaiting_approval → queued | rejected | expired
    queued → running
    running → validating_result | failed | timed_out
    validating_result → awaiting_review | failed
    awaiting_review → accepted | changes_requested
    changes_requested → validating

非终态可请求取消；running / validating_result 通过 cancel_requested → cancelled 收束，其他非终态可直接 cancelled。accepted、rejected、expired、cancelled 为终态；failed / timed_out 可由有权用户显式重试，按当前模板策略进入 validating / awaiting_approval / queued。重试或 changes_requested 创建新 Run，旧 Run 不覆盖。审批过期默认 24 小时；新的申请可创建新的任务版本。

工具执行前以数据库事务比较 task.version、当前状态、取消标记、ACL 和批准；取消后不再发出新调用。已经发生的外部副作用不会被取消自动回滚。

### 7.4 批准语义

候选审批场景是执行前的 start_template_run：可考虑对 prepare_handoff 要求负责人确认来源范围与预算，其他模板是否需要审批由后续策略确定。访客申请时，负责人审核必须基于明确的临时会话和请求上下文；批准不能扩大其可读取范围。执行中发现范围外工具请求应拒绝，不能通过模型自行扩权。该能力尚未实现。

审批记录应绑定 action_type、规范化参数摘要、输入版本摘要、策略版本、批准人、有效期和一次性消费记录；变化后失效。负责人自行发起任务时的确认规则，以及访客会话结束后的任务访问方式尚待确定；确定前不启用依赖该规则的真实执行。

审批等待不占用 Worker。通过后原子消费批准，授权该执行代次，并重新检查当前权限再入队。该代次内的至多 2 次基础设施重试沿用同一输入、工具和累计预算，不重复消费批准；输入变化、用户显式重试或返工创建新执行代次并重新执行审批策略。MVP 未开放的动作，即使有人点批准也不能执行；需要先修改和部署版本化策略。任务结果接受与动作执行批准是不同记录。

## 8. 架构与执行方式

### 8.1 方案取舍

| 方案 | 取舍 |
|---|---|
| 问答 + 表单 | 快，但无法验证异步任务闭环。 |
| 模块化单体 + 独立 Worker（本文建议） | 权限、审计与事务集中；后台进程可单独伸缩。 |
| 通用自主 Agent 平台 | 灵活，但首版授权及恢复复杂度过大，暂缓。 |

Pi 是已确认的 Agent 运行时方向；具体模型供应商、生产部署和其他技术细节仍需验证。

### 8.2 组件

- Web：React / TypeScript。项目知识管理、问答、问题、任务和个人状态表单。
- API：FastAPI。所有身份、ACL、状态迁移、批准及文件下载鉴权。
- PostgreSQL：结构化业务表、JSONB 状态、审计、任务及 transactional outbox。
- 对象存储适配器：本地开发目录；试点可接组织批准的 S3 兼容服务。下载须经 API 校验，不暴露永久公共地址。
- Worker：轮询领取任务和导入作业，使用租约 / 心跳；每项在独立工作目录和受限进程中执行。
- Tool Gateway：服务端唯一工具执行入口，按真实请求者、项目、输入、策略与预算授权。
- Pi RuntimeAdapter / ModelAdapter：将 Pi、模型供应商与工作台授权边界解耦；开发期提供可测试的模拟实现。
- 负责人生产身份来源待确定，可评估企业 OIDC；临时访客不因此变为长期账号。开发期假身份只允许本机使用且禁止生产开启。

Codex 用于开发与验证平台；产品运行时不把 Codex 桌面聊天记录作为业务数据库或任务队列。外部适配器启用前须核对官方接口、组织授权和部署可行性，本文不承诺某一账户已具有相应能力。

### 8.3 持久执行

1. 创建 Task 和 outbox 事件在同一事务提交；返回持久任务 ID。
2. 领取器使用行锁与租约，仅一个有效持有者处理同一执行代次。建议租约 60 秒、心跳 15 秒。
3. 每次领取产生单调 fencing_token；工具网关拒绝过期 token，防止旧 Worker 复活后继续执行。
4. 每步保存 RunStep、输入 / 输出摘要、来源和检查点，再进入下一步。
5. 基础设施错误按策略重试；证据校验失败或模型输出不合规不自动无限重跑。
6. 已知完成的步骤跳过；副作用状态不明时标记 reconciliation_required，人工或适配器对账后处理。
7. MVP 工具不开放外部写入；平台内部事件使用幂等键去重。未来外部写入需支持幂等或对账，不能声称 exactly-once。

### 8.4 受控 ReAct 与 Skills

读取检查点 → 提出结构化动作 → Schema / 权限 / 预算校验 → 工具执行 → 保存观察和证据 → 决定继续或结束。启动审批在入队前完成；执行中发现材料不足时形成明确缺项的结果，由人工补充并发起新代次，不在运行中自动扩权。

首版 Skills：answer-approved-knowledge、analyze-build-log、triage-mde-issue、prepare-handoff。每个 Skill 固定输入输出契约、例子、版本及允许的动作类型。Skill 文本不能更改服务端工具权限；资料和日志中的指令只能作为数据。首版动作级人工门控限于 start_template_run，不为无真实业务场景的执行中审批搭建通用框架。

三层验证：结构有效、证据可定位、模板业务条件满足。第二模型可作为辅助评审，但不能替代工具返回值、确定性校验或人工验收。只记录可审计动作、简明决策理由和证据，不依赖保存模型内部思维链。

## 9. 数据模型与契约

所有表使用 UUID 主键、UTC 时间，界面以 Asia/Shanghai 或用户选择时区展示。可变聚合记录使用 version 乐观锁。用于交付的编号如 R-023 是项目内唯一显示编号，不替代主键。

| 实体 | 必要字段及关系 |
|---|---|
| Owner / GuestSession / Project | 负责人身份、临时会话、项目和明确的访问范围；不建立同事长期账号。 |
| KnowledgeSource / SourceVersion | project_id、类型、对象键 / 对话快照、摘要、ACL、敏感等级、保留策略。 |
| ImportJob | 来源版本、状态、解析器版本、进度、错误、租约、重试、草稿输出引用。 |
| KnowledgeEntry / KnowledgeVersion | 项目、模块、类型、负责人、版本化正文 / 结构字段、发布与工程状态、复核标记、来源。 |
| KnowledgeChunk | 所属版本、文本、来源 locator、索引版本及授权索引键；索引不是权限真源。 |
| KnowledgeRelation / Baseline | 类型、两端版本、确认人；基线冻结的版本与关系映射。 |
| PersonalStatus / PersonalStatusVersion | subject_user_id、手动内容、受众、发布状态、published_at、manual_updated_at。 |
| PersonalActivity / WeeklyAllocation | 所属状态版本、可选项目 / 任务引用、周起始日、unit、planned、actual、手动进度。 |
| Question / Answer / AnswerEvidence | 请求者、项目 / 基线、问题、回答、知识 / 个人状态版本及具体证据。 |
| Issue / IssueRevision | 工程上下文、描述、证据、负责人、状态、版本和迁移记录。 |
| Task / Run / RunStep | 模板及版本、输入快照、请求者、状态、预算、租约、fencing_token、检查点、验证报告。 |
| Approval / ResultReview | 执行动作批准及其消费；结果接受 / 返工。不能互相替代。 |
| Artifact | 内容摘要、对象键、类型、来源依赖、访问范围、保留 / 撤销状态。 |
| AuditEvent / OutboxEvent | actor / principal_type、动作、对象、前后版本摘要、关联 ID、结果；追加写入。 |

核心 JSON 契约定义在 contracts/：TaskInput、RunCheckpoint、ToolAction、TaskResult、SourceLocator、PersonalStatusInput。全部带 schema_version，拒绝未知动作类型、非法单位和多余敏感控制字段。

工具动作必有 task_id、run_id、step_id、tool、arguments、fencing_token。授权身份来自服务端运行上下文，不取自模型或 JSON 参数。

TaskResult 必有 summary、findings、evidence、missing_information、proposed_next_steps、validation；业务结论不能只靠 success=true。SourceLocator 按来源类型限定 slide_number、paragraph_id 或 line_start / line_end 等字段。

RunCheckpoint 保存执行代次、已完成 step ID、待执行动作及其摘要、启动审批 ID、材料版本引用和预算消耗。不保存 API key、访问令牌或完整敏感工具输出。

## 10. 权限、凭证与审计

| 动作 | 临时访客 | 负责人 | 后台运行上下文 |
|---|---|---|---|
| 读取知识、问答、下载 | 仅当前明确开放且有效的内容 | 本人有权管理的内容 | 按具体请求和工具授权 |
| 提交问题 | 在当前允许的项目内提交 | 查看并人工处理 | 不得自行关闭问题 |
| 发布 / 停用知识 | 不允许 | 人工操作 | 不允许直接发布 |
| 任务申请 / 执行批准 | 可在明确开放的能力范围内申请；目标能力尚未实现 | 按待确定的审批规则操作 | 仅在服务端策略和授权范围内执行 |
| 编辑 / 发布个人工作状态 | 不允许 | 本人手动操作 | 不允许 |

身份恢复和配置管理不得通过伪造负责人身份写入个人状态。访客的会话 ID 只能标识临时会话，不能证明其真实身份。

- 所有服务端资源访问统一调用授权服务；对象存储 key、搜索索引和图关系不是授权凭证。
- 衍生产物的有效受众为所有来源许可范围的交集；当前访问时再次检查来源是否撤销。权限撤销后，缓存答案、下载链接和旧版不得继续泄露内容。
- 系统无法追回用户已经下载的副本；需在组织数据治理中说明这项限制。
- 凭证仅由服务端保管；模型不能读取。MCP 最小权限、逐工具授权，禁止把负责人的高权限凭证当作全团队通用身份。
- 文件解析和工具进程默认无外网，只允许显式配置的目标；防止路径穿越、压缩炸弹、任意 URL 读取和宏执行。
- 审计事件追加写入，应用角色不允许修改旧事件，定期独立备份；不宣称数据库管理员无法篡改。
- 日志脱敏，页面不暴露完整敏感请求或令牌；按 actor / task / project 的 correlation_id 查问题。

## 11. 实施路线与发布边界

从当前原型出发，优先补齐问题与知识生命周期，再推进 Pi 和有出处的回答、受控任务与审批，最后完成生产身份、部署和试点评估。实际优先级可随使用反馈调整；依赖尚未确定的会话、项目开放和审批规则不能被提前当作已定方案。

具体现状、待决事项及验收步骤见 [实施计划](workbench-implementation-plan-v0.1.md)。
接真实工程数据或部署到团队环境前，必须确定组织允许的数据存放位置、模型处理环境、身份提供方和保留政策。上述配置不阻塞本地模拟模式开发，不以猜测代替上线决策。
