# 个人工作台实施计划

状态：以当前本地原型为起点，按单负责人、临时访客模型继续实施。本文是剩余工作计划，不代表所有目标已经实现或可以试点。需求和设计依据见 [需求与设计基线](workbench-requirements-design-v0.1.md)；实际启动方式和限制见 [README](../README.md)。历史任务、接口草案和测试思路保存在 [原计划归档](archive/workbench-implementation-plan-original.md)，其中多人账号和角色设计已经废弃。

## 1. 已确认的边界

- 工作台只有一位长期负责人。同事通过链接使用临时会话，不创建同事长期账号，不建设项目成员管理。
- 项目组织知识和问题；项目知识列表、源文件和个人状态要求负责人明确开放；问答在启用 Agent 后可读取所选项目全部已发布知识，因此回答可能透露未开放的内容。草稿和已停用知识不进入问答。
- “关于我”的内容、进度和投入只能由负责人手动维护；访客、知识导入、对话、Agent、Worker 和任务结果均无写入路径。
- Agent 运行时方向为 Pi；MVP 不安装、不运行、不依赖 EverOS。只读问答已接入 Pi，默认关闭模型；保留未来替换记忆实现的边界，不提前宣称已有 EverOS 适配能力。
- 当前账号、临时会话、SQLite 和本地存储仅供开发；一键启动绑定本机，不等于对同事开放的部署。真实部署、数据、身份及模型环境须单独验证。
- 代码遵循 [开发铁律](../AGENTS.md)，包括 Clean Code、必要注释、并发与资源管理、日志和审计。验收须说明实际覆盖范围。

## 2. 当前实现与缺口

以下为当前本地原型状态；这不是试点或生产验收结论。

| 能力 | 本地原型已有 | 尚未完成 |
|---|---|---|
| 身份与个人状态 | 开发账号登录、临时访客会话；负责人手动保存、发布、撤回状态及部分项目投入 | 正式负责人认证、生产会话管理、完整状态字段和投入可视化 |
| 知识导入 | Markdown/TXT、DOCX/PPTX 文件及手动文字；选择或输入项目内特性模块，旧知识默认公共知识；独立 Worker、草稿预览、人工发布；旧版 Office 给出转换提示 | 对话消息快照导入、草稿编辑、旧格式隔离转换、Office 原图对照、编码确认及重试 |
| 知识管理 | 按项目、状态、文件名浏览；下载原件、发布、访客可见性、停用 | 分类、条目关系、真正的版本演进与比较、基线、恢复、保留清理 |
| 访客问答 | 只读目录与分段阅读、来源完整性校验；启用后由 Pi 自主选择所选项目已发布知识生成回答，支持会话内有限连续追问和实时处理步骤，校验引用编号并在调用后复核状态；出错时降级 | 语义事实验证、个人状态问答、基线、持久化对话、转问题单、模型限流和费用预算 |
| 问题 | 访客先查看共享问题列表及分析状态，再通过弹窗登记项目、功能模块、现象和可选日志；同一会话的页面重试使用幂等键防止重复登记；所有访客可手动提交串行 Agent 分析，无日志也可分析；报告展示模型提供的每轮 token 消耗；负责人可按版本流转、重开或关闭问题 | 限流、存储保留、附件管理、日志归档真实环境兼容性与生产权限 |
| 部署与配置 | 本地安装启动脚本与模型、代理配置；API 和 Worker 输出按进程滚动的结构化日志，关联请求与任务 ID | Windows 实机验证、团队可访问的生产部署、真实身份、备份恢复、日志集中采集与跨进程文件保留策略 |

Pi 原型已使用模拟模型验证只读工具执行，并用真实 DeepSeek 和临时合成数据验证自主查阅项目知识再回答的链路；这不代表所有供应商、真实工程数据或生产环境已验证。模型子进程没有操作系统级只读沙箱，撤权也无法追回已发送给模型服务的数据。

当前原型已加入上下文窗口预算校验及超时原因区分。问题分析的 token 统计取自模型服务，未提供统计不等于零，未记录统计的历史分析无法追溯；供应商统计的完整性和精确性仍需验证。上下文压缩和生产环境验证仍待完成。

问答实时步骤只展示处理进展，不展示模型内部思维链；其访问仍受项目和会话权限约束。步骤不代表最终结果，失败或断连时不能将已显示的进度视为成功回答。

当前项目知识列表只包含至少有一条对访客开放的已发布知识的项目；问题登记可选所有项目，问题与报告对所有访客可见。负责人状态流转保留旧版 `new → resolved` 接口兼容，新的状态接口需要处理说明和期望版本。

### 近期完成的本地原型

- 问题中心默认展示共享列表和分析状态；登记弹窗支持可选日志，无日志时仍可基于描述和可用资料分析。现有问题和原日志继续兼容。
- 知识和文本 Skill 可绑定项目特性模块；问题分析自动匹配项目内该模块及公共 Skill，并在提交报告时复核匹配内容。问题登记可选择已发布知识及启用 Skill 的模块名。
- 同一临时会话内的登记重试使用幂等键；相同问题当前只能有一个排队或运行中的分析，所有访客可以查看问题和报告。
- 问题分析记录可分页查看每次任务的 token 用量；缺失统计显示未知，不完整的统计标明部分用量。问答实时展示有限的处理步骤并支持页面内连续追问。
- 负责人可以填写说明，按版本分诊、处理、解决、重开或关闭问题；状态更新和审计在同一事务中提交。
- API 和 Worker 输出结构化日志，可通过请求、问题和任务标识关联排查；日志保留、集中收集和生产访问控制仍未完成。

以上能力以本地开发配置为范围。合入 `4306163` 时的自动回归结果为后端 174 项、前端 57 项通过，另有 Agent 测试通过；无日志分析使用模拟 Agent 覆盖。上述结果不代表真实模型端到端、PostgreSQL 多进程、Windows 或生产环境已验证。

## 3. 待决策的产品与运行边界

这些问题不阻塞与之无关的本地开发，但相关能力上线前必须确定并记录：

1. **项目开放：** 访客已可向所有项目登记问题，问题与报告对访客共享；对外部署时的入口和授权策略仍需确定。
2. **会话和找回：** 临时会话、问题和任务各自的保留期限；离开页面后是否需要找回，以及如何通过不可猜测、可撤销的凭证授权。不能把任务 ID 当作访问凭证。
3. **审批：** 访客发起与负责人发起的任务分别如何确认；何种动作必须由负责人批准、超时和配置变更如何处理。不能假设存在代理审批人或第二个长期账号。
4. **生产环境：** 负责人身份认证、同事网络入口与安全边界、模型和数据处理环境、备份及保留策略。生产配置不得复用开发身份。
5. **模型范围：** 不同供应商的 API URL、model、思考强度及能力差异；具体 API 和费用限制需按实际供应商验证。此前允许的真实 DeepSeek 凭证仅在必要验证时按用户授权使用，不写入代码或日志。

## 4. 后续工作顺序与验收

下列顺序是实施建议，可按实际使用反馈调整；每项先编写针对性失败测试，完成实现后运行相关测试，并按改动风险补充权限、并发与资源验证。只在验收条件全部满足时标记完成，不因已有局部原型而提前勾选。

### 4.1 稳固基础与问题闭环

- [x] 问题登记支持同一会话内的幂等键及页面重试，重复请求复用原结果；键复用于不同内容时拒绝。刷新或会话失效后不保证自动去重。
- [ ] 为问题登记和分析请求增加限流及存储保留策略；分析请求尚无独立幂等键，验证多进程和目标数据库的重复提交行为。
- [x] 实现问题状态流转、重开、版本冲突和审计；原有 `new`、`resolved` 数据保持可用，旧版直接解决接口继续兼容。
- [ ] 在目标 PostgreSQL 环境验证问题状态并发变更和审计事务。
- [ ] 完善问题字段、附件预算、负责人筛选与关联知识；访客可浏览所有问题与报告，仍需完善附件管理及生产权限。
- [ ] 测试访客越权、不同会话隔离、重复提交、并发状态变更、共享撤销、正文和凭证不进入日志；在实际目标数据库验证事务行为。

涉及：`apps/api/workbench/issues/`、`apps/api/workbench/guests.py`、`apps/web/src/GuestIssues.tsx`、`apps/web/src/OwnerIssues.tsx` 和相关测试。当前实现部分仍位于 `app.py`，重构时应保持 API 兼容并避免无关改动。

### 4.2 知识生命周期和来源

- [ ] 支持负责人编辑草稿并生成可追溯的新知识版本；已发布正文不能原地覆盖。明确停用、重新发布和来源依赖的迁移与并发冲突处理。
- [ ] 完善导入恢复和重试、错误状态、文件与文本大小边界；Office 文件按目标实现隔离转换、原件对照及修订 / 图片核对，旧格式无转换器时保持明确提示。
- [ ] 实现分类、可确认的关系、版本比较、基线和缺项视图；开放范围变化后，知识列表、原件下载、关系图及基线须按各自授权规则处理；问答遵循已确认的全部已发布知识范围。
- [ ] 实现明确的来源与产物保留 / 清理策略；有效引用不得被误清理，显式撤销或合规删除时先处理依赖。
- [ ] 测试跨项目授权、来源完整性、历史版本、并发编辑、撤权后旧引用、导入失败清理、Office 不安全输入及实际数据库锁行为。

涉及：`apps/api/workbench/knowledge/`、`apps/api/workbench/jobs/`、`apps/web/src/KnowledgeImport.tsx`、`apps/web/src/KnowledgeManager.tsx`。关系、基线和迁移模块按设计新增；历史接口名称仅供参考。

### 4.3 Pi、模型与有出处的回答

当前本地原型允许模型直接回答通用问题；涉及项目事实时提供限定项目的知识目录和分段阅读工具，由 Pi 自主选择资料；模型配置显式启用，支持预算、超时及可选环境代理；引用编号及调用后知识状态会复核；无引用回答会标注，超时、繁忙和上下文超限有独立提示，失败时回退到原文。单次提问最多 30 次工具调用、12 次分段读取，每段最多 3000 字符；最近 5 轮保存在进程内。只读工具不提供文件写入、脚本执行或 Shell，子进程尚无操作系统级沙箱。以下是仍需完成的工作：

- [ ] 补全提示注入、模型输出和引用的语义事实验证；引用编号存在不等于回答内容一定正确。模型不得因知识中的指令改变访问范围或获取写入工具。
- [ ] 增加访问频率、跨进程并发和累计 token / 费用预算，并验证超时、取消、资源释放和失败重试。评估操作系统级隔离；目前工具层只读不代表进程级沙箱。
- [ ] 完善精确 token 计数与上下文压缩、供应商 / 模型能力差异与生产密钥管理。当前仅支持配置 DeepSeek 兼容 HTTPS API；模型服务会收到访客问题、有限对话历史及已发布知识片段，包括未对访客开放的知识。
- [ ] 为个人状态问答、对话保存、基线查询及转问题单分别定义权限与证据契约并实现；不将当前有界工具调用的原型视为完整问答。
- [ ] 在模拟服务覆盖提示注入、异常输出、撤权、超时、取消和预算；真实供应商验证使用用户授权的脱敏样例，记录测试范围，不输出凭证。

涉及：`apps/api/workbench/questions/`、`apps/agent/`、`apps/api/workbench/guests.py`、服务端配置和 `apps/web/src/GuestQuestions.tsx`。EverOS 不作为依赖或验收前提。

### 4.4 受控后台任务和审批

- [ ] 完善当前只读问题分析任务的报告追溯、格式兼容和实际环境验证，并为问题分诊及交接准备定义版本化契约。现有命令为受限只读操作。
- [ ] 完善 Skill 版本演进、编辑与恢复、历史快照和审计查询；验证 PostgreSQL 并发更新和实际模型下的匹配效果。当前 Skill 为项目内有界文本，停用后可重新录入，不执行脚本。
- [ ] 在 API 和独立 Worker 中实现持久状态、租约、心跳、fencing、预算、重试、取消、恢复与幂等；执行前重新校验来源和授权。
- [ ] 对需要确认的动作实现负责人审批、输入与策略摘要绑定、过期、变更失效和一次性消费；负责人自发任务如何确认须遵循第 3 节最终决定。
- [ ] 结果先验证再人工验收；Agent 不能自动关闭问题、修改个人状态或扩大数据受众。测试失效租约、恢复、重复领取、审批并发、取消竞态和证据失败。

### 4.5 生产身份、部署和试点

- [ ] 明确负责人认证、访客入口、安全会话、TLS、跨进程会话与资源授权；不得以当前开发账号 / 进程内会话直接对外提供服务。
- [ ] 验证 PostgreSQL 多进程事务、Worker 故障恢复、对象存储、备份恢复、文件清理与审计保留；明确容量、限流、日志、监控及密钥管理。
- [ ] 在 Windows 实机验证 `setup.cmd`、`start.cmd`、进程树关闭及路径含空格；在目标环境验证 Linux/macOS 过程。本地启动器不是生产部署工具。
- [ ] 使用授权的脱敏样本进行端到端与安全测试，并记录问题、限制及人工判断。目标评测样本为 20 个问题、10 份日志和 10 张历史问题单；未完成时不声称达到试点门槛。

## 5. 回归与交付标准

- 负责人手工状态、访客访问边界、来源下载与撤销、上传预算、问题登记、任务授权、日志脱敏和错误反馈按改动范围回归。
- 单元测试不能代替浏览器实际体验、PostgreSQL 多进程 / 故障测试或真实部署验证；记录实际命令、结果、警告及未覆盖项。
- 依赖按后端 `uv.lock`、Pi Agent 的 `package-lock.json` 和前端 `pnpm-lock.yaml` 锁定。更改配置字段时同步示例、校验、使用文档和兼容策略，绝不提交真实凭证。
- 交付前检查 `main` 和开发分支的状态，按用户要求进行本地合并；远程推送、真实环境部署或对外开放应按明确授权执行。
