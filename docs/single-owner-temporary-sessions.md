# 单负责人、临时访客的工作台边界说明

状态：用户已确认同事通过链接直接进入非管理员临时会话。当前需求和实施顺序以 [设计基线](workbench-requirements-design-v0.1.md) 与 [实施计划](workbench-implementation-plan-v0.1.md) 为准；本文件保留边界说明及待决事项。

## 已明确的方向

- 工作台内部只有一个长期主体：负责人本人。负责人维护项目知识、人工发布的工作状态、任务策略与审批。
- 外部同事通过工作台链接直接访问，不创建长期账号，也不要求负责人逐个添加为项目成员。同事进入时获得彼此隔离的临时会话，用于使用被允许的工作台功能。
- 只有经过验证的负责人本人可编辑、发布或撤回“关于我”；临时访客、文件导入、Agent 和后台任务不具备个人状态写入权限。
- 项目是知识组织和问答的边界。项目知识列表、原件及个人状态须由负责人明确开放；启用 Agent 后，问答可使用所选项目全部已发布知识，包括未开放列表和下载的内容。草稿和已停用知识不进入问答。任何能访问链接的人均可建立访客会话并使用这些访客能力。

## 待确定的产品边界

- 会话结束或过期后，会话令牌、聊天内容、问题单和后台任务分别保留多久；临时身份不自动意味着所有业务记录立即删除。
- 无长期身份时，如何让同事在离开页面后安全地找回自己提交的任务；不能把猜测得到的任务 ID 当作授权。
- 执行审批如何适配单负责人：访客或负责人本人发起的任务分别如何确认、哪些任务需要审批，如何避免将临时会话误认为已核验身份。
- 问题登记和问答可选择所有项目；登记的问题与分析报告对所有访客可见。问题附件如何删除、长期保留和对外部署时如何授权仍需确定。

当前实现不将现有成员关系或旧版已发布内容自动转换为访客公开权限。

## 初步实现影响

1. 将服务端主体区分为负责人人工会话、临时访客会话和受限后台执行上下文；访客不继承负责人凭证或权限。
2. 逐步替换多用户配置和成员管理界面，原项目与个人状态数据须保留；数据库结构的废弃或迁移另行设计，不静默删除历史记录。
3. 重做知识检索、原件下载、个人状态和任务的服务端授权，覆盖会话过期、撤销和资源可见性变化；日志与审计使用不暴露令牌的关联标识。
4. 在前端分别提供负责人管理入口和临时会话入口；临时会话之间的隔离和持久任务结果的安全读取仍须随相关功能实现。
5. 加入针对访客伪造负责人身份、越权写入、会话相互读取、过期、撤销和后台任务权限的测试；真实身份接入前继续仅使用脱敏本地数据。

问答与原件下载是不同授权范围：回答及引用片段可能向访客透露未开放下载的已发布内容。外部模型会收到访客问题、有限历史、Agent 查看过的知识目录信息和读取的知识片段；已发送的数据无法因后续停用而撤回。当前临时会话只用于本地开发，不能作为真实身份认证。
