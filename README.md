# HMW 个人工作台

HMW 是一个以项目知识为基础的个人工作台。负责人维护工作状态和知识；同事通过链接进入临时访客会话，查看负责人明确开放的内容、进行知识问答或登记问题。

当前是**本地开发原型**，不能用于真实敏感数据、团队试点或对外部署。正式身份认证、生产会话、限流、数据保留与备份等能力仍未完成。详见 [实施计划](docs/workbench-implementation-plan-v0.1.md)。

## 当前功能

- **负责人：** 创建项目，手动维护、发布或撤回工作状态；导入、预览和发布知识，控制访客可见性；查看访客问题并手动标记解决。访客可以共享查看问题并手动发起后台分析。
- **访客：** 使用临时会话，查看开放的工作状态与知识、下载对应原件、在项目中提问或登记问题。问答和问题登记可选择所有项目；项目知识列表只包含有访客开放知识的项目。
- **知识导入：** 支持 UTF-8 Markdown/TXT、DOCX/PPTX 及手动输入文字。文件先由独立 Worker 处理，生成草稿后须由负责人确认发布。
- **问一问：** 支持连续追问和实时展示分析步骤；步骤是可展示的处理进展，不展示模型内部思维链。显式启用模型后，通用问题可直接由模型回答；涉及项目事实时，Pi Agent 可通过只读目录和分段阅读工具自主查阅所选项目全部已发布知识（包括未开放访客查看的知识），生成带来源编号的回答；草稿和已停用知识不参与问答。未启用模型时仅检索已开放知识原文。项目知识列表和原件下载始终要求访客开放权限。

MVP 不接入 EverOS。Pi 模型默认关闭；未来长期记忆可另行评估接入。

## 一键安装与启动

### 1. 安装依赖

需要 Python 3.12+、`uv`、Node.js 22.19+、`npm` 和 `pnpm`。在仓库根目录运行：

| 系统 | 命令 |
|---|---|
| Linux / macOS | `./scripts/setup.sh` |
| Windows 命令提示符 | `scripts\setup.cmd` |

Linux / macOS 也可以使用 `sh scripts/setup.sh`。脚本根据 `apps/api/uv.lock`、`apps/agent/package-lock.json` 和 `apps/web/pnpm-lock.yaml` 安装锁定依赖，可重复执行，不会启动服务或设置密码。

### 2. 创建配置

将仓库根目录的 [config.example.toml](config.example.toml) 复制为 `.hmw.toml`，填写负责人开发账号和密码：

```toml
[owner]
username = "owner"
password = "填写本地开发密码"

[server]
api_port = 8000
web_port = 5173
```

`.hmw.toml` 已加入 Git 忽略列表。自定义路径也可作为启动脚本的第一个参数，但需要自行确保它不会被提交。不要把密码或 API key 写进受版本控制的文件。

### 3. 启动服务

| 系统 | 命令 |
|---|---|
| Linux / macOS | `./scripts/start.sh` |
| Windows 命令提示符 | `scripts\start.cmd` |

Linux / macOS 也可以使用 `sh scripts/start.sh`；在 `scripts` 目录下可运行 `sh start.sh`。启动器依次启动 API、导入 Worker 和前端，等待 API 与前端就绪后显示访问地址。默认地址为 `http://127.0.0.1:5173`；按 `Ctrl+C` 停止。API 和 Worker 使用同一数据库 `apps/api/workbench-dev.db` 和文件目录 `apps/api/workbench-objects/`。

服务仅监听本机 `127.0.0.1`。Windows 脚本及进程树清理尚未在 Windows 实机验证。重启 API 后需要重新登录负责人账号，已有临时访客会话也会失效。

### 常见启动问题

- 提示端口不可用时，先确认是否已有工作台在运行；可在 Linux 使用 `ss -ltnp`，在 Windows 使用 `netstat -ano` 查看监听进程。停止确认属于工作台的旧实例，或修改 `.hmw.toml` 中的端口后重新启动。
- 提示配置格式无效时，检查 TOML 语法；`llm.enabled` 必须写成不带引号的 `true` 或 `false`，修改配置后重启服务。
- 切换分支或更新代码后，重启工作台以加载新的后端实现；重启会使本地负责人登录和临时访客会话失效。

## 使用工作台

1. 点击“负责人登录”，使用 `.hmw.toml` 中配置的账号密码登录并创建项目。
2. 在“导入知识”中上传文件，或展开“手动输入文字”。提交后等待 Worker 处理，预览草稿，再点击发布。
3. 如需访客在“项目知识”浏览或下载原件，在发布时勾选“允许临时访客查看此知识”；也可在“知识管理”中调整。默认不开放列表和原件。启用 Agent 问答后，即使未勾选，访客仍可能通过回答或引用片段获知该项目的已发布知识。
4. 访客进入工作台后，在“问一问”选择项目连续提问，也可在“项目知识”浏览开放内容、在“登记问题”提交问题。负责人在“问题中心”查看。

导入状态会自动刷新约一分钟，之后可手动刷新。若任务一直等待领取，请检查 Worker 是否运行，以及 API 与 Worker 是否使用相同的数据库和文件目录。DOC/PPT 旧格式需先转换为 DOCX/PPTX；Word 未解决的修订会阻止导入，批注和图片需要人工核对。

## 启用只读 Pi 问答

编辑 `.hmw.toml` 中的 `[llm]`，显式启用 DeepSeek 兼容的 HTTPS API，然后重启工作台：

```toml
[llm]
enabled = true
api_key = "填写模型服务密钥"
model = "deepseek-v4-pro"
api_url = "https://api.deepseek.com"
reasoning_effort = "off"
max_output_tokens = 4096
context_window_tokens = 1048576
max_context_bytes = 200000
max_answer_chars = 12000
timeout_seconds = 180
```

`reasoning_effort` 支持 `off`、`low`、`high`、`max`；`off` 会明确向 DeepSeek 请求关闭思考，其他值会启用相应强度。示例默认关闭，思考强度及参数支持情况以具体供应商为准。缺省值见下表。

| 配置 | 含义及允许范围 | 缺省值 |
|---|---|---:|
| `max_output_tokens` | 每次模型调用的输出 token 上限，1–32768 | 1024 |
| `context_window_tokens` | 提供给 Pi 的模型总窗口参数，2–1048576，须大于输出上限 | 131072 |
| `max_context_bytes` | 每次发送前对序列化上下文执行的 UTF-8 字节上限，1024–1000000 | 200000 |
| `max_answer_chars` | 返回回答的字符上限，1–65536；历史每轮仍只保留最多 4000 字符 | 4000 |
| `timeout_seconds` | 单次 Agent 执行总超时，1–900 秒 | 90 |

每次模型调用前，工作台从总窗口中预留输出 token，再按每个 UTF-8 字节占一个 token 保守估算输入，并同时检查字节上限。检查包括历史与工具结果。超限时提示开始新对话，并在有可用资料时展示原文。实际 token 数以模型服务的分词结果为准。DeepSeek 官方 V4 Pro 的窗口和最大输出分别为 1048576 和 393216 token，但本项目为了资源控制将单次输出配置上限设为 32768；选择其他服务商时应按其实际能力调整。

### 公司代理和直连例外

默认 `proxy_mode = "direct"`，Agent 不继承系统代理。如需按环境变量使用代理，配置：

```toml
[network]
proxy_mode = "environment"
# 可选：配置值优先于同名环境变量；不写则继承进程环境。
# https_proxy = "http://proxy.example:3128"
# http_proxy = "http://proxy.example:3128"
# no_proxy = "localhost,127.0.0.1,.corp.example"
# ca_file = "/path/to/company-ca.pem"
```

支持 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 及小写形式；`no_proxy` 是模型 API 地址的直连例外。配置值若为空字符串，会覆盖对应环境变量。`ca_file` 可指定公司受信任的额外 CA，未设置时可继承 `NODE_EXTRA_CA_CERTS`。该配置用于 Agent 的模型请求，不更改启动器本地健康检查；不要把带凭据的代理地址提交到 Git。代理模式需要 Node.js 22.21+（22.x）或 24+，不支持 SOCKS / `ALL_PROXY`。修改后重启工作台。

启用后，访客问题、有限的对话历史、Agent 查看过的知识目录信息和主动读取的已发布正文片段（包括未开放访客查看的知识）会发送到配置的模型服务，使用前请确认数据与供应商处理环境适合该用途。

Pi 只注册项目知识目录与分段读取工具，不接收负责人密码或数据库配置；工具无法修改知识、创建脚本、执行命令或读取其他项目。Agent 子进程以启动工作台的系统用户身份运行，目前没有操作系统级沙箱，不能将工具只读视为进程层面的写入隔离。返回前会校验引用编号并重新检查来源状态和项目归属；原件下载仍单独检查访客可见性。若模型不可用，页面降级展示已校验的原文。访客可能从回答及引用片段间接获知未开放下载的已发布知识，请按此范围决定发布内容。未引用项目资料的通用回答会明确标注，不应作为项目事实；**编号校验不能保证回答事实正确，请核对来源。** 知识状态以工具读取和回答前复核时为准，并发停用可能发生在复核之后；已发送到模型服务的数据无法撤回。

实时步骤受同一项目和会话权限约束，不改变知识或原件的访问范围。步骤只是进度，不能代替最终回答及来源校验；请求失败或连接中断时，已显示的进度不代表回答成功完成。

## 访客问题分析

访客选择项目，填写功能模块、问题现象并上传日志后，可在共享问题列表中点击“分析问题”。所有访客均可查看问题及分析报告。分析任务排队执行，同一数据库同时只运行一个分析任务；日志附件上限为 10 MiB，历史问题没有日志时不能发起分析。

提交时若网络中断，可在当前页面直接重试：对同一次未确认的提交，使用相同内容和日志重试只会创建一条问题；修改表单或重新选择文件会作为新的提交。刷新页面或临时会话失效后，原重试标识不会保留，请先查看共享问题列表。该机制不包含访问限流。

在 `.hmw.toml` 配置分析工程目录，并启用上面的 `[llm]` 设置：

```toml
[analysis]
code_root = "/path/to/code"
skill_root = "/path/to/skills" # 可选
```

Agent 可自主读取所选项目的已发布知识、上传的日志以及上述目录中的文件。只读命令支持 `pwd`、`ls`、`cat` 和普通文本搜索 `rg`，不执行任意脚本或 Git 命令。日志支持 ZIP、TAR、TAR.GZ 和 RAR，RAR 需要系统安装支持 RAR 的 libarchive；已用临时 libarchive 和公开 RAR 样本验证读取。归档访问有条目数、展开大小和单文件大小限制。Windows 缺少安全的目录描述符读取能力时分析工具会拒绝文件访问，该环境尚未验证。Windows 上 Worker 意外中断后，处于 running 的任务需人工恢复，避免旧任务仍在运行时重复分析。

分析可能将日志、代码片段、技能文件及知识内容发送到配置的模型服务。工作台重启后需要重新进入临时会话，已登记的问题和报告保存在数据库中。

问题分析记录可展示每次任务累计的 token 消耗，以模型服务返回的统计为准。缺失或无法区分的全零统计显示为未知；统计不完整时显示已知的最低消耗。历史分析未记录的消耗无法追溯，进程或主机异常退出前尚未保存的统计可能丢失。分析失败或中断不视为成功报告，已有问题及报告仍按访客共享范围访问。

## 当前限制

- 负责人账号和访客会话只供本地开发；访客会话在进程内保存，最长 8 小时。没有正式身份、跨进程会话或生产网络访问方案。
- 尚未实现模型调用限流、跨进程并发限制和累计费用预算。本地数据库或文件系统发生长时间阻塞时，配置的 Agent 超时无法中断底层 I/O。
- 问答历史仅保存在进程内，按临时会话和项目隔离，最多保留最近 5 轮、1000 个对话，最长 8 小时；刷新页面或切换项目开始新对话。Agent 的目录支持分页，单次提问最多读取 12 段、每段 3000 字符，工具调用最多 30 次；因此它可以选择查阅整个项目，但每次回答无法读取无限资料；尚无个人状态问答、基线查询或从回答直接转问题单。
- 还没有草稿编辑、知识分类、关系、版本对比、保留清理，以及 Office 隔离转换、OCR 或原图对照。非 UTF-8 文本需转换后上传。
- 问题登记和分析请求还没有幂等键与访问限流；网络失败后重试可能产生重复问题。当前只支持一个日志附件和有限的分析状态，尚无完整问题状态流转。
- 当前主要使用 SQLite 和本地文件，未完成 PostgreSQL 多进程竞争、长时间阻塞与故障恢复、断电清理和生产部署验证。审计查询、数据库级防篡改和保留清理尚未实现。

API 和 Worker 的应用日志默认同时输出到终端及 `apps/api/workbench-logs/`。文件分别为 `api-进程号.jsonl`、`worker-进程号.jsonl`，每个文件达到 5 MiB 时滚动，最多保留 3 个备份。可通过环境变量 `HMW_LOG_DIR` 指定目录；POSIX 下目录须仅对当前用户开放，日志文件权限为 `0600`。Windows 下日志继承目录 ACL，当前尚未验证自动设置私有 ACL，部署时须由管理员配置。不同进程使用不同文件，旧进程文件不会自动清理，需要按部署环境设置保留策略和磁盘监控。

排查时先从接口响应头 `X-Request-ID` 查找请求事件，再通过其中关联的问题 ID、分析 ID 或导入任务 ID 查找 Worker 事件。日志包含任务领取、排队与执行耗时、执行代次、状态、工具类型和有限的错误分类；意外异常记录异常类型及代码位置，不记录异常原文。日志不包含问句、文件内容、工具路径、模型密钥或会话凭据。知识和问题等关键成功操作还记录独立的审计元数据，不以日志代替审计。启动器自身及 Uvicorn 的进程启动信息仍输出在终端；模型供应商错误原文和子进程 stderr 不持久化。若导入或分析一直排队，可先核对终端及 Worker 文件中是否存在 `worker_started`，再用任务 ID 查找领取和执行事件。

## 验证

在安装依赖后，从仓库根目录运行：

```sh
uv run --directory apps/api pytest
node --test apps/agent/test/readonly.test.mjs apps/agent/test/explore.test.mjs
pnpm --dir apps/web test
pnpm --dir apps/web build
```

后端自动测试主要使用 SQLite 和显式测试身份，不能代替 PostgreSQL 多进程、真实身份、浏览器端到端或生产安全验证。真实模型验证只应使用授权的脱敏样例，不应在日志或测试输出中打印凭证。
