# HMW 个人工作台

HMW 是一个以项目知识为基础的个人工作台。负责人维护工作状态和知识；同事通过链接进入临时访客会话，查看负责人明确开放的内容、进行知识问答或登记问题。

当前是**本地开发原型**，不能用于真实敏感数据、团队试点或对外部署。正式身份认证、生产会话、限流、数据保留与备份等能力仍未完成。详见 [实施计划](docs/workbench-implementation-plan-v0.1.md)。

## 当前功能

- **负责人：** 创建项目，手动维护、发布或撤回工作状态；导入、预览和发布知识，控制访客可见性；查看访客问题并手动标记解决。
- **访客：** 使用临时会话，查看开放的工作状态与知识、下载对应原件、在项目中提问或登记问题。项目知识与问题登记的项目列表要求至少一条对访客开放的已发布知识；问答可选择所有项目。
- **知识导入：** 支持 UTF-8 Markdown/TXT、DOCX/PPTX 及手动输入文字。文件先由独立 Worker 处理，生成草稿后须由负责人确认发布。
- **问一问：** 支持针对所选项目连续追问。显式启用模型后，Pi Agent 可通过只读目录和分段阅读工具自主查阅该项目全部已发布知识（包括未开放访客查看的知识），生成带来源编号的回答；草稿和已停用知识不参与问答。未启用模型时仅检索已开放知识原文。项目知识列表和原件下载始终要求访客开放权限。

MVP 不接入 EverOS。Pi 模型默认关闭；未来长期记忆可另行评估接入。

## 一键安装与启动

### 1. 安装依赖

需要 Python 3.12+、`uv`、Node.js 22.19+、`npm` 和 `pnpm`。在仓库根目录运行：

| 系统 | 命令 |
|---|---|
| Linux / macOS | `./scripts/setup.sh` |
| Windows 命令提示符 | `scripts\setup.cmd` |

Linux / macOS 也可以使用 `sh scripts/setup.sh`。脚本根据 `apps/api/uv.lock`、`apps/agent/package-lock.json` 和 `apps/web/pnpm-lock.yaml` 安装锁定依赖，可重复执行，不会启动服务或设置密码。

### 2. 创建配置

将仓库根目录的 [config.example.toml](config.example.toml) 复制为 `.hmw.toml`，填写负责人开发账号和密码：

```toml
[owner]
username = "owner"
password = "填写本地开发密码"

[server]
api_port = 8000
web_port = 5173
```

`.hmw.toml` 已加入 Git 忽略列表。自定义路径也可作为启动脚本的第一个参数，但需要自行确保它不会被提交。不要把密码或 API key 写进受版本控制的文件。

### 3. 启动服务

| 系统 | 命令 |
|---|---|
| Linux / macOS | `./scripts/start.sh` |
| Windows 命令提示符 | `scripts\start.cmd` |

Linux / macOS 也可以使用 `sh scripts/start.sh`；在 `scripts` 目录下可运行 `sh start.sh`。启动器依次启动 API、导入 Worker 和前端，等待 API 与前端就绪后显示访问地址。默认地址为 `http://127.0.0.1:5173`；按 `Ctrl+C` 停止。API 和 Worker 使用同一数据库 `apps/api/workbench-dev.db` 和文件目录 `apps/api/workbench-objects/`。

服务仅监听本机 `127.0.0.1`。Windows 脚本及进程树清理尚未在 Windows 实机验证。重启 API 后需要重新登录负责人账号，已有临时访客会话也会失效。

### 常见启动问题

- 提示端口不可用时，先确认是否已有工作台在运行；可在 Linux 使用 `ss -ltnp`，在 Windows 使用 `netstat -ano` 查看监听进程。停止确认属于工作台的旧实例，或修改 `.hmw.toml` 中的端口后重新启动。
- 提示配置格式无效时，检查 TOML 语法；`llm.enabled` 必须写成不带引号的 `true` 或 `false`，修改配置后重启服务。
- 切换分支或更新代码后，重启工作台以加载新的后端实现；重启会使本地负责人登录和临时访客会话失效。

## 使用工作台

1. 点击“负责人登录”，使用 `.hmw.toml` 中配置的账号密码登录并创建项目。
2. 在“导入知识”中上传文件，或展开“手动输入文字”。提交后等待 Worker 处理，预览草稿，再点击发布。
3. 如需访客在“项目知识”浏览或下载原件，在发布时勾选“允许临时访客查看此知识”；也可在“知识管理”中调整。默认不开放列表和原件。启用 Agent 问答后，即使未勾选，访客仍可能通过回答或引用片段获知该项目的已发布知识。
4. 访客进入工作台后，在“问一问”选择项目连续提问，也可在“项目知识”浏览开放内容、在“登记问题”提交问题。负责人在“问题中心”查看。

导入状态会自动刷新约一分钟，之后可手动刷新。若任务一直等待领取，请检查 Worker 是否运行，以及 API 与 Worker 是否使用相同的数据库和文件目录。DOC/PPT 旧格式需先转换为 DOCX/PPTX；Word 未解决的修订会阻止导入，批注和图片需要人工核对。

## 启用只读 Pi 问答

编辑 `.hmw.toml` 中的 `[llm]`，显式启用 DeepSeek 兼容的 HTTPS API，然后重启工作台：

```toml
[llm]
enabled = true
api_key = "填写模型服务密钥"
model = "deepseek-chat"
reasoning_effort = "off"
api_url = "https://api.deepseek.com"
```

`reasoning_effort` 支持 `off`、`low`、`high`；具体模型的支持情况以服务商为准。启用后，访客问题、有限的对话历史、Agent 查看过的知识目录信息和主动读取的已发布正文片段（包括未开放访客查看的知识）会发送到配置的模型服务，使用前请确认数据与供应商处理环境适合该用途。

Pi 只注册项目知识目录与分段读取工具，不接收负责人密码或数据库配置；工具无法修改知识、创建脚本、执行命令或读取其他项目。Agent 子进程以启动工作台的系统用户身份运行，目前没有操作系统级沙箱，不能将工具只读视为进程层面的写入隔离。返回前会校验引用编号并重新检查来源状态和项目归属；原件下载仍单独检查访客可见性。若模型不可用，页面降级展示已校验的原文。访客可能从回答及引用片段间接获知未开放下载的已发布知识，请按此范围决定发布内容。没有引用的回答会明确标注为未依据项目知识，不应作为项目事实；**编号校验不能保证回答事实正确，请核对来源。** 知识状态以工具读取和回答前复核时为准，并发停用可能发生在复核之后；已发送到模型服务的数据无法撤回。

## 当前限制

- 负责人账号和访客会话只供本地开发；访客会话在进程内保存，最长 8 小时。没有正式身份、跨进程会话或生产网络访问方案。
- 尚未实现模型调用限流、跨进程并发限制和累计费用预算。本地数据库或文件系统发生长时间阻塞时，进程超时无法中断底层 I/O。
- 问答历史仅保存在进程内，按临时会话和项目隔离，最多保留最近 5 轮、1000 个对话，最长 8 小时；刷新页面或切换项目开始新对话。Agent 的目录支持分页，单次提问最多读取 12 段、每段 3000 字符，工具调用最多 30 次；因此它可以选择查阅整个项目，但每次回答无法读取无限资料；尚无个人状态问答、基线查询或从回答直接转问题单。
- 还没有草稿编辑、知识分类、关系、版本对比、保留清理，以及 Office 隔离转换、OCR 或原图对照。非 UTF-8 文本需转换后上传。
- 问题登记还没有幂等、限流、附件、访客进度查询或完整状态流转；网络失败后重试可能产生重复记录。
- 当前主要使用 SQLite 和本地文件，未完成 PostgreSQL 多进程竞争、长时间阻塞与故障恢复、断电清理和生产部署验证。审计查询、数据库级防篡改和保留清理尚未实现。

API 请求日志记录路由、状态、耗时和请求 ID，不记录正文、查询参数或会话凭据；知识和问题等关键成功操作记录审计元数据，不以日志代替审计。

## 验证

在安装依赖后，从仓库根目录运行：

```sh
uv run --directory apps/api pytest
node --test apps/agent/test/readonly.test.mjs apps/agent/test/explore.test.mjs
pnpm --dir apps/web test
pnpm --dir apps/web build
```

后端自动测试主要使用 SQLite 和显式测试身份，不能代替 PostgreSQL 多进程、真实身份、浏览器端到端或生产安全验证。真实模型验证只应使用授权的脱敏样例，不应在日志或测试输出中打印凭证。
